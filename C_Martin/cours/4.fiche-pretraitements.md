<a id="s3"></a>
## 3. De la donnée à la connaissance : cycle de fouille

**Cycle de fouille de données** (diapo 11) :

*Données sources* → **Consolidation des données** → *Données consolidées* (entrepôt) → **Sélection et prétraitement** → *Données préparées* → **Fouille de données** → *Motifs & modèles* → **Interprétation et évaluation** → **Connaissance**, avec des **retours en arrière** possibles vers chaque étape.

**La préparation des données** — souvent **long**… et **coûteux** :
1. « **Nettoyer** » les données ;
2. Remplir les **valeurs manquantes** (ou éliminer des données) ;
3. **Normaliser** les données (si utile) ;
4. Changer la **représentation**.

<a id="s4"></a>
## 4. Pourquoi des prétraitements ? Intégration de sources multiples

**Aller chercher les données** : ex. recueillir des données sur les **préférences alimentaires** — comment faire ? (questionnaires, tickets de caisse, bases existantes… → sources hétérogènes).

**Intégration et transformation** = fusionner différentes sources :
- **identifier les entités** (ex. `client_id` et `cl_nr`) ;
- **uniformiser les unités** (ex. DOLLAR et EURO) ;
- **convertir** les adresses en coordonnées ;
- calculer la **vente quotidienne** à partir des ventes individuelles ;
- **normaliser** les variables entre 0 et 1 ;
- remplacer toute valeur $x$ d'un attribut $A$ de moyenne $\mu$ et variance $\sigma^2$ par $\dfrac{x - \mu}{\sigma}$ → moyenne 0 et variance 1.

**Problèmes potentiels**

| Intrinsèques aux données | Relatifs à la collecte |
|---|---|
| **Valeurs manquantes** | **Points aberrants** (*outliers*) |
| **Bruit** (sur la description ou sur la classe) | **Classes déséquilibrées** |
| **Attributs redondants** | |
| **Attributs non pertinents** | |
| **Dimensions hétérogènes** : domaines de variation très différents ; valeurs numériques / symboliques | |

## 5. Types de données (rappel)

> 💡 On **représente les données par rapport aux objectifs visés**.

| Type | Exemples | Propriétés |
|---|---|---|
| **Nominales** | Sexe, profession | Nombre de valeurs **dénombrable** ; **aucune relation d'ordre** ; opérateurs arithmétiques **inapplicables** |
| **Ordinales** | Taille (petite, moyenne, grande) | Des **modalités** ; **relation d'ordre** entre modalités ; calculs sur des **rangs** |
| **Numériques** discrètes ou continues | Âge, poids | Nombre de valeurs **théoriquement infini** ; relation d'ordre ; notion de **distance et d'écart** ; calculs **arithmétiques** possibles |

<a id="s6"></a>
## 6. Symbolique → numérique

Transformer des données **symboliques** (nominales ou ordinales) en données **numériques** :

| Cas | Méthode | Exemple |
|---|---|---|
| Ensemble **avec proximité sémantique** | **Séquence d'entiers** | [rouge, vert, bleu] → [1, 2, 3] |
| Ensemble **sans proximité sémantique** | **Code correcteur d'erreur** | voir ci-dessous |
| Toute variable nominale | **Codage disjonctif complet** | voir ci-dessous |

### Codes correcteurs d'erreur

> 💡 On cherche à **maximiser le nombre de bits différents entre codes** (sommets éloignés sur le cube $\{0,1\}^3$).

| Message $E$ | Code $F(E)$ |
|---|---|
| 0 0 | 0 0 0 |
| 0 1 | 1 0 1 |
| 1 0 | 1 1 0 |
| 1 1 | 0 1 1 |

> 🔎 Les 4 codes sont à **distance de Hamming 2** deux à deux (jamais voisins sur le cube) : aucune valeur n'est artificiellement « plus proche » d'une autre, contrairement au codage par entiers. En plus, une erreur sur un bit donne un mot invalide, donc **détectable**.

### Codage disjonctif complet (*one-hot*)

**Un attribut booléen par valeur possible** : $N$ valeurs → $N$ nouveaux attributs.

| Profession | Architecte | Agronome | Médecin | Pilote |
|---|---|---|---|---|
| Architecte | 1 | 0 | 0 | 0 |
| Agronome | 0 | 1 | 0 | 0 |
| Médecin | 0 | 0 | 1 | 0 |
| Pilote | 0 | 0 | 0 | 1 |
| Agronome | 0 | 1 | 0 | 0 |

> ⚠️ Coder une variable **sans ordre** par des entiers (1, 2, 3) crée un **ordre et des distances artificiels** (« bleu » serait 2 fois plus loin de « rouge » que « vert »). Ce codage n'est légitime qu'avec une **proximité sémantique** réelle (variable ordinale).

<a id="s7"></a>
## 7. Numérique → symbolique : discrétisation

| Méthode | Principe |
|---|---|
| **Equal-width binning** | Données en $k$ intervalles de **même taille** |
| **Equal-frequency binning** | Données en $k$ groupes contenant approximativement le **même nombre d'exemples** |
| **Division par seuil entre classes** | Guidée par des **connaissances extérieures** : autres éléments des données, connaissances du domaine |

**Exemple du cours** : Data = 0, 4, 12, 16, 16, 18, 24, 26, 28 ($k = 3$).

| | Bin 1 | Bin 2 | Bin 3 |
|---|---|---|---|
| **Equal width** | 0, 4 → $[-, 10)$ | 12, 16, 16, 18 → $[10, 20)$ | 24, 26, 28 → $[20, +)$ |
| **Equal frequency** | 0, 4, 12 → $[-, 14)$ | 16, 16, 18 → $[14, 21)$ | 24, 26, 28 → $[21, +)$ |

Histogrammes : equal width → effectifs **2 / 4 / 3** ; equal frequency → **3 / 3 / 3**.

> 🔎 Largeur d'un intervalle en *equal width* : $\dfrac{\max - \min}{k}$ (ici $28/3 \approx 9{,}3$, arrondi à 10 dans la diapo). Les seuils d'*equal frequency* sont pris **entre** deux valeurs consécutives (14 entre 12 et 16 ; 21 entre 18 et 24).

<a id="s8"></a>
## 8. Numérique → numérique : normalisation

**Cas de domaines de variation très différents** → cela **fausse les régularités** trouvées (une variable à grande échelle domine les distances).

- Fréquemment : **normalisation centrée réduite**.
  - **Centrée** : on ramène tous les domaines de variation **autour de 0** (on retire la moyenne) ;
  - **Réduite** : on **divise par l'écart-type**.
- Ou : toutes les dimensions dans **[0, 1]**.

Hypothèses : attribut $A$ de moyenne $\mu$, d'écart-type $\sigma > 0$, de minimum et maximum $\min(A) < \max(A)$.

$$x_{\text{cr}} = \frac{x - \mu}{\sigma}$$

🔎 Mise dans [0, 1] (min-max) :

$$x_{[0,1]} = \frac{x - \min(A)}{\max(A) - \min(A)}$$

- $x$ : valeur d'origine
- $\mu$, $\sigma$ : moyenne et écart-type de $A$
- $x_{\text{cr}}$ : centrée réduite (moyenne 0, variance 1)
- $x_{[0,1]}$ : normalisation min-max (formule non écrite dans les diapos)

> ⚠️ **Ce n'est pas forcément une bonne idée — pas de réponse unique :**
> 1. **Identifier des groupes de personnes** : est-ce qu'**un mètre est équivalent à un kilo** ? (les unités n'ont pas de commune mesure → normaliser peut se justifier, mais c'est un **choix**).
> 2. **Analyse des villes au Canada** : les distances **est-ouest > nord-sud** ; c'est une **vraie** propriété géographique → **sans doute une bonne idée de ne pas normaliser**.

**Indications pratiques :**
1. Utiliser les transformations **à bon escient** ;
2. En **essayer plusieurs** ;
3. Examiner les **résumés** du jeu de données ;
4. **Visualiser** les données **avant et après** transformation ;
5. **Extraire de l'information**.

<a id="s9"></a>
## 9. Nettoyage : bruit, aberrants, qualité

**Les « données »** : formats **différents**, sources **hétérogènes**, descriptions **imparfaites** (données **manquantes**, **fausses**, attributs **redondants**, **non pertinents**). Problèmes : classes **très déséquilibrées**, **points aberrants**, **grandes dimensions**.

### Données bruitées

| Types de bruit | Modèle de bruit |
|---|---|
| Sur la **description** (attributs) | **Gaussien** ? |
| Sur la **classe** (étiquette) | **Uniforme** ? |
| | **Variable**, avec **indication de fiabilité** ? |

### Données aberrantes

| | Exemple | Détection / remarque |
|---|---|---|
| **Valeurs aberrantes** | âge = 123 ans ; tél : 999-999-999 | Comparaison à des **contraintes d'intégrité** |
| **Points aberrants** | Sur **plusieurs dimensions** | Peuvent être de **vrais points**, mais **faussent les statistiques** |

> 🔎 Un **point aberrant multidimensionnel** peut avoir chaque valeur plausible séparément (ex. 1,90 m et 45 kg) : c'est la **combinaison** qui est atypique, d'où la difficulté de détection.

### Qualité des données

> 💡 **GIGO : Garbage In, Garbage Out.**

- **Omniprésent** dans toutes les applications ;
- **Complexe** : intrinsèque dans toute BD, entrepôt ou SI ; frontière bonnes/mauvaises données **imprécise** ;
- **Critique** : coûte énormément.

<a id="s10"></a>
## 10. Valeurs manquantes et imputation

### Pourquoi des valeurs manquantes ?

| Cause | Exemples | Nature |
|---|---|---|
| **Défaut de mesure** | Défaut de transmission ; mesure en dehors des valeurs permises | Manquantes de manière **aléatoire** |
| **Tous les attributs ne sont pas renseignés** | Patients dans les hôpitaux (on ne fait pas tous les examens à tout le monde) | Manquantes de manière **non aléatoire** |

> 🔎 Dans le cas non aléatoire, **le fait même qu'une valeur manque est une information** (un examen non prescrit dit quelque chose de l'état du patient) : l'imputer « naïvement » peut introduire un biais.

**Exemple du cours (vaches) :**

| Vache | Sexe | Âge | Conso. 1er jour | Conso. 2e jour | Poids |
|---|---|---|---|---|---|
| Bérénice | F | 3 | 3,56 kg | 3,87 kg | 630 kg |
| Marguerite | ? | 5 | 4,78 kg | ? | ? |
| Blanchette | F | ? | ? | 5,72 kg | 435 kg |
| Furie | M | 6 | 6,02 kg | ? | 875 kg |

Les valeurs sont **souvent indispensables** → comment faire ?

**Stratégies simples :**
1. **Élimination** des données touchées ;
2. **Remplacement par la valeur la plus fréquente** ;
3. **Autant d'exemples fictifs que de valeurs possibles** (avec **pondération**).

> 🔎 Stratégie 3 : pour Marguerite (sexe ?), on crée deux copies, une « F » et une « M », pondérées par la fréquence de chaque sexe dans les données (ex. 2/3 et 1/3). C'est ce que font par exemple certains arbres de décision (C4.5).

### Imputation

| Méthode | Risque |
|---|---|
| **Retrait de l'attribut** | **Retire de l'information** : catastrophique si l'attribut est **important** ou si **beaucoup d'attributs** sont touchés |
| **Valeur moyenne de l'attribut** | Peut modifier considérablement la **distribution**, en particulier en **sous-estimant la variance** |
| **Valeur moyenne de l'attribut dans cette classe** | Peut **propager des erreurs** |
| **Interpolation** | Prédire la valeur manquante **à partir des autres attributs**, ou à partir de **règles** (« si étudiant ⇒ âge < 25 ans ») |

> 🔎 Pourquoi la moyenne sous-estime la variance : toutes les valeurs imputées sont **égales** à la moyenne, donc elles n'ajoutent **aucun écart** ; la variance calculée ensuite est plus petite que la vraie.
> ⚠️ 🔎 « Moyenne **dans cette classe** » utilise l'**étiquette** : en apprentissage supervisé, à ne faire que sur l'ensemble d'**apprentissage** (sinon fuite d'information vers le test).

<a id="s11"></a>
## 11. Réduction de dimension

| Approche | Principe | Exemples |
|---|---|---|
| **Sélection d'attributs** | **Choix** d'un sous-ensemble des attributs initiaux | — |
| **Extraction d'attributs** (redescription) | **Création** de nouveaux attributs par **combinaison** des attributs initiaux | **Linéaire** (plus simple) : ACP, ACI… ; **non linéaire** : Isomap, *Locally Linear Embedding* (LLE), t-SNE… **mais pas de méthode systématique** |

**Attributs redondants ou non informatifs** (diapo 44) :
- **Redondants** : les deux attributs $x$ et $y$ **apportent la même information** (les projections sur $x$ ou sur $y$ séparent aussi bien les deux clusters) → un seul suffit.
- **Non informatif** : $y$ **ne permet pas de distinguer** les deux clusters (leurs projections sur $y$ se chevauchent) → seul $x$ est utile.

### Analyse en Composantes Principales (ACP)

- Méthode **linéaire**.
- Calcule les **composantes principales** (axes **orthogonaux**) **préservant l'essentiel de l'inertie (la variance)** du jeu de données.
- Optimise un **critère quadratique** → ➢ **très sensible aux points aberrants**.

> 🔎 Les axes $F_1, F_2, \dots$ sont les **vecteurs propres** de la matrice de covariance (ou de corrélation si les données sont centrées réduites), rangés par **valeur propre décroissante** = part de variance expliquée. On projette chaque individu $i$ sur ces axes ($F_1(i), F_2(i)$) et l'on garde les premiers.

<a id="s13"></a>
## 13. Pièges à éviter

| Piège | Ce qu'il faut retenir |
|---|---|
| Coder une nominale sans ordre par 1, 2, 3 | Crée un ordre et des distances **artificiels** → codage disjonctif ou code correcteur |
| Normaliser systématiquement | **Pas de réponse unique** : ex. villes du Canada, mieux vaut **ne pas** normaliser |
| Croire que centrée réduite = [0, 1] | Centrée réduite : moyenne 0, variance 1 (valeurs non bornées) |
| Confondre equal width et equal frequency | Width : intervalles de **même largeur** ; frequency : **même effectif** |
| Imputer par la moyenne sans y penser | **Sous-estime la variance**, déforme la distribution |
| Imputer par la moyenne de la classe partout | Peut **propager des erreurs** ; utilise l'étiquette (fuite si fait sur le test) |
| Supprimer un attribut incomplet par réflexe | Catastrophique s'il est important ou si beaucoup d'attributs sont touchés |
| Supposer que les manquants sont aléatoires | Ils peuvent être **non aléatoires** (patients) |
| Valeur aberrante = point aberrant | Valeur : une seule variable, détectée par contraintes d'intégrité ; point : plusieurs dimensions, peut être réel |
| Appliquer l'ACP sans regarder les aberrants | Critère **quadratique** → très **sensible** aux aberrants |
| Sélection = extraction d'attributs | Sélection : **sous-ensemble** des attributs ; extraction : **nouveaux** attributs combinés |

<details>
<summary><b>Question 13 (5 pts) :</b> Qu'est-ce que l'ACP calcule, et pourquoi est-elle sensible aux points aberrants ? <i>(Cliquez ici pour la réponse)</i></summary>
<br>

</details>
